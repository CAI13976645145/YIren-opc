1. 它是什么

「一人公司」是一个本地运行的 AI 公司控制台：

  • 唯一的人类是你（老板 / CEO）。所有"员工"都是真实的模型会话，不是假数据。
  • 每个员工有独立工位目录、独立角色卡（preset）、独立工具权限，互不串味。
  • 工作以项目组织：项目有团队、工作区、预算、Git 快照；任务落到具体员工。
  • 员工干完活把文件放在自己的工位，你点「交付」收取，验收通过才算完成。
  • 员工要改已有文件、对外发消息，会先停在你面前等你审批。
  • 公司有记忆（Markdown 落盘）、技能/工具/专家目录、日报周报、会议、审计日志、账本。

三句话记住三个循环：

循环你在做什么在哪里
招聘 → 授权给员工岗位、工具、技能、专家员工 / 公司资产
立项 → 开工建项目、组队、建任务、让员工开工项目 / 任务
交付 → 验收收工位文件、看预览、通过或打回交付物 / 预览台 / 收件箱

2. 5 分钟跑起来

2.0 桌面客户端（推荐）

如果你拿到的是 一人公司-Setup-<版本>.exe：

  1. 双击安装（可选安装目录），桌面会出现「一人公司」快捷方式
  2. 启动后会先在托盘常驻，窗口自动打开 http://127.0.0.1:4399
  3. 关闭窗口只是收起到托盘；右键托盘图标可以「打开 / 重启服务 / 开机自启 / 检查更新 / 退出」
  4. 数据在 %APPDATA%\one-company-desktop\data，日志在同目录 logs\

桌面端会自动带起 Web 服务与 DSH 运行时，不需要再开两个终端。

0.24 起 DSH 运行时已内嵌：安装包自带独立 Node 24 与 @deepseek-ai/dsh 全部依赖（约 325 MB），目标机器不需要安装 Node.js，也不需要联网拉包。首次启动会把默认 profile 初始化到 %APPDATA%\one-company-desktop\data\dsh-home。

2.1 启动

需要 Node.js 18+（只有 Web 版需要；桌面安装版已内置运行时）。在项目目录执行：

cd one-company
npm start            # Web 客户端 → http://127.0.0.1:4399

另开一个终端启动 AI 运行时（真正干活的 dsh 控制面）：

npm run dsh          # 本地控制面 → 127.0.0.1:3081

浏览器打开 http://127.0.0.1:4399。

两个都要开：Web 是"公司前台"，dsh 是"员工的大脑"。只开 Web 时页面能看，但员工不会回话。

2.2 配置模型（第一次必做，有引导）

全新安装第一次打开，会自动弹出配置向导，不用自己找设置：

  1. 欢迎页 → 点「开始配置」
  2. 选一个预设（DeepSeek / 通义千问 / Moonshot / OpenAI / 本地 Ollama），或直接手填：

| 字段 | 说明 | 示例 | | --- | --- | --- | | 名称 | 只用于界面展示 | DeepSeek | | API 端点 | OpenAI 兼容地址，通常以 /v1 结尾 | https://api.deepseek.com/v1 | | API 密钥 | 只存在本机 data/settings.json | sk-... | | 模型 ID | 一行一个；可点「测试连接」自动拉取 | deepseek-chat |

  1. 点 测试连接：显示「连接成功 · N 个模型」就说明端点和密钥都对
  2. 点 保存并继续 → 确认默认模型 → 进入工作台

保存后会生成 data/runtime/dsh-model.patch.yml，AI 运行时启动时自动带上。

点「稍后再说」会先跳过，主界面顶部会常驻一条黄色提示，点「立即配置」可以随时重新打开向导。

2.2.1 添加多个模型服务

模型设置页支持配置任意多个 OpenAI 兼容服务，互不覆盖：

  • 添加：设置 → 模型设置 → 右上「＋ 添加模型服务」→ 填完保存
  • 切换默认：在某个服务上点「设为默认」，或点它下面的模型芯片
  • 编辑 / 删除：每行右侧的操作按钮；删除默认服务会自动切到下一个可用服务
  • 扫描模型：点「扫描模型 / 测试连接」会实时拉取该服务的 /models 列表，自动填入模型表格，并按模型名推测图片、思考能力
  • 能力配置：每个模型可单独设置「图片输入」「思考（reasoning）」「上下文窗口」「最大输出 tokens」；保存后会写入 dsh-model.patch.yml，视觉模型会自动声明 input: image，思考模型会声明 reasoningEfforts
  • 手动添加：扫描不到时可以在模型表格上方输入模型 ID，点「添加」再配置能力

默认模型用于所有员工会话；需要按岗位/项目分流时，用「模型路由」页签覆盖。

不再需要改配置文件。旧版本只有一组 provider/baseUrl/apiKey/model 字段，升级时会自动迁移成一条「模型服务」记录，不会丢配置。

2.3 自检

  • 右上角显示 本地运行
  • 设置 → 运行状态：控制面 ok、模型补丁存在
  • 底部对话坞选「秘书 Agent · 江叙」，发一句"在吗"，能逐字回你就通了

4. 第一次招聘：让公司有人

4.1 两种招聘方式

打开 员工 页，右上角：

按钮适用
招聘员工从零填：姓名、岗位、部门、描述、工具、技能、权限等级、模型（留空按岗位自动匹配）
按岗位模板招聘选岗位模板，自动带出岗位职责、默认工具、默认技能、专家和合适的模型

推荐用岗位模板：模板里的工具/技能/专家会自动装好，新人第一天就能干活。

4.2 招聘时到底发生了什么

点下"保存"后，系统会：

  1. 创建员工档案，直接绑定工作区：默认 data/workspaces/company/employees/<员工ID>/，也可填本机已有绝对路径
  2. 注册一张原生角色卡 emp-<员工ID>（岗位、职责、工具面、技能、专家都写进去）
  3. 在 dsh 控制面注册这个 preset（热更新，不用重启）
  4. 把技能、工具写入公司目录（如果目录里还没有）
  5. 按岗位匹配专家并双向绑定
  6. 按岗位自动匹配模型：研发/财务/审阅优先推理型，内容/设计优先视觉型，客服/行政优先快速型；也可以手动指定模型和思考强度
如果角色卡注册失败，接口会返回 warning，员工仍会创建，但会回退到 standard preset。设置 → 运行状态里能看到。

4.3 人事行政专员（沈舟）

公司默认有一位 人事行政专员 · 沈舟，他负责招聘、员工档案，也负责维护公司资产：

范围可用工具
招聘 / 员工 / 权限list_catalog、list_employees、contact_employee、hire_employee、update_employee、assign_skills、assign_tools、assign_experts、request_permission
机房 / 服务器list_servers、save_server、delete_server、save_service、delete_service、scan_server_services、register_server_services
设备list_devices、read_device、save_device、delete_device
工具 / 技能 / 专家save_tool、save_skill、save_expert、delete_expert
知识库 / 资产盘点save_memory、list_memories、company_asset_overview、audit_company
任务 / 账本 / 文档create_task、list_tasks、update_task、ledger_summary、list_documents、read_document

所以你可以直接对他说：

"帮我招一个短视频编导，偏运营，先放到《长夜》项目里。"
"把 ComfyUI 工作站登记到机房，地址 192.168.110.5，下面挂 ComfyUI 8188 端口。"
"盘点一下公司现在有哪些服务器、设备、工具和专家。"

他会读岗位模板目录 → 选模板 → 招聘 → 分配工具/技能/专家 → 拉进项目，然后向你汇报；资产类操作会写审计日志。

职责基线：招聘、员工档案、权限、工具/技能/专家目录、知识库、机房服务器、设备资产、公司资产盘点与公司体检。对应的技能已同步为：招聘、岗位设计、权限管理、员工档案、工具目录维护、技能目录维护、专家库维护、知识库维护、服务器台账、服务登记、设备资产管理、公司资产盘点、对账、事实核对。

秘书 · 江叙是项目总负责人：老板只给目标、边界和最终目的，他负责把需求问清、拆成里程碑与任务、分配给合适员工、跟踪执行、验收成果、不合格打回并继续推进下一步，直到达成目标。不是每一步都等老板安排；只有目标不清、预算/权限/风险越界或需要老板拍板时才问。对应技能：目标拆解、项目管理、项目推进、交付验收、项目资料维护、排期、日报、数据复盘、审阅、质量把关、归档、知识库维护、工具目录维护、预算管理。

4.4 员工状态

状态含义

空闲可接单
等待审批有写操作卡在你这里

4.5 离职与交接

员工页 → 更多 → 归档：

  • 有未完成任务时必须选交接人，否则不允许归档
  • 任务、团队成员、项目编制会自动转给交接人
  • 历史会话、交付物、账本、审计全部保留，可按员工筛选追溯
  • 归档会写一条"离职交接"公司记忆
  • 随时可恢复

5. 从项目到交付：一条完整流水线

5.1 立项

左栏 新建项目：

字段说明
项目名称必填
类型研发 / 运营 / 知识（决定配色与默认模板）
工作区可填本机绝对路径；不填则自动建在 data/workspaces/projects/<项目ID>
团队选一个已存在的团队，成员会自动进项目编制
预算 / 预警线账本按项目汇总，超预警线会提醒
截止展示用，可随时改

创建后会自动打一个 初始 Git 快照（影子仓库，不污染你的真实仓库）。

5.2 组队

两种方式：

  1. 项目卡片 → 编辑 → 团队：选团队，成员自动同步
  2. 员工 → 编辑 → 项目：把某个人拉进项目

项目编制决定：谁能在这个项目里被 @、谁能接这个项目的任务、群聊时谁发言。

5.3 建任务

任务 → 新建任务：

字段说明
标题必填，一句话说清交付什么
项目 / 负责人决定工位与权限
优先级低 / 中 / 高 / 紧急
截止展示 + 提醒
验收标准会写进员工的任务提示词，越具体越好
前置任务填任务标题或 ID，未完成时不允许开工
纳入自动开工队列打开后，空闲员工会自动接单
任务级隔离区打开后员工在 Git worktree 里干活，验收通过才合并

5.4 开工

任务行右侧：

  • 开工 / 重跑：让负责人现在执行
  • 停止：中断当前运行，保留断点
  • 继续：从断点接着做（lastRun.status = interrupted 时显示）
  • 超时保护：单个任务最长 15 分钟（TASK_TIMEOUT_MS 可调）；超时不会丢结果，保留已完成内容、工具记录和断点，按「继续」接着做
  • 执行中：任务行会显示员工当前在做什么（思考中 / 调用某工具 / 输出中）
  • 交付：从员工工位收取交付物
  • 归档：任务移入「已归档」，不再出现在活跃列表、自动开工和项目工作流里；任务页顶部可切换「活跃 / 已归档」并恢复，也可以一键「归档已完成」
  • 编辑：改任务、看最近执行结果、看任务交付物

并行规则：

  • 全局并发槽位 1–4（任务页顶部可调，默认 2）
  • 同一个员工不会并行：他手上有一个在跑，第二个会排队
  • 前置任务未完成 → 直接拒绝开工
  • 员工已归档 → 拒绝开工

5.5 员工执行时发生了什么

  1. 进入该项目的专属工位（不是员工公共目录）
  2. 带上角色卡 + 岗位说明 + 项目上下文 + 相关记忆 + 绑定的专家
  3. 读文件、写文件、跑命令（受工具面限制）
  4. 写已有文件前 → 调审批服务 → 停住等你
  5. 完成后把产物写进工位，任务转「待验收」，交付物进你的交付物列表
  6. 全过程写审计、记 Token 账本、发通知

5.6 新项目里员工能写代码吗（实测）

能。实测流程（新建项目 → 组一个研发员工 → 建代码任务 → 开工）：

环节实测结果
项目工作区自动创建，带初始 Git 快照
员工工位自动创建 stations/<项目>/<员工>
写文件员工用 read / write / edit 直接落盘，实测产出 todo.py（约 6.8KB）+ README.md
审批新建文件 L1 自动放行；修改已有文件 L2 需要你批准，一次代码任务可能连弹 2–3 条
归档任务成功后工位文件自动同步进项目工作区
交付物自动登记「任务名.md」，并列出本次归档的工位文件

三个注意点：

  1. 批准时勾「本会话内同类放行」：这样同一员工同一文件在 30 分钟内不再重复问你，代码任务会顺很多。
  2. 员工没有终端工具：现在只能读写文件，不能自己跑 python todo.py 或测试，验证要你来做（后续可加 bash 工具 + 沙箱策略）。
  3. 单任务最长 5 分钟：超时会中断，但工位里已经写好的文件会自动归档成「部分产出」交付物，不会丢；可以在交付物里查看，打回让员工继续。
如果任务一直停在「进行中」，先看收件箱有没有待批准的写操作——员工很可能在等你点头。

5.7 秘书能替你做什么（公司工具）

秘书（以及所有员工）通过一组公司工具操作真实数据，不再靠"记忆"回答：

工具作用
list_catalog读岗位模板、工具、技能、专家、员工目录
list_employees在职员工档案、岗位、技能、负载
list_projects项目列表（ID / 名称 / 类型 / 状态 / 进度 / 人数）
create_project新建项目（自动建工作区 + 初始快照）
scan_projects扫描已有目录，识别还没登记的旧项目，可一键登记
save_tool新建/更新公司工具目录（秘书、人事可用），再分配给员工
update_project维护项目名称、描述、状态、版本、用户数、技术栈、快捷入口、合同金额、笔记
audit_company公司体检：scope=project 检查项目描述、技术栈、入口、成员、里程碑、知识、收支、证书、运维；scope=company 检查公司信息、工具、技能、专家、知识库、服务器、设备、员工模型、模型能力、备份
repair_company把体检发现的缺口生成维护任务，派给秘书/人事
hire_employee仅人事行政按岗位模板招人；秘书不直接招人，只整理岗位需求交给人事
contact_employee所有员工默认具备：先 list_employees 查同事 ID，再说清背景、要对方做什么、什么时候要；会等对方回复并把原话带回来。沟通记录同时写进双方对话，标「同事沟通」
ask_user发选择式提问：单选/多选、多问题、逐条作答

选择式提问会以卡片形式出现在对话里，点「开始回答」后可选项，也可以直接在「其他答案 / 补充说明」里输入自己的答案；多选时输入内容会追加到已选项后面。答案提交后会自动回填给员工继续推进。

秘书现在能看到全公司的员工名单与项目列表；普通员工只看到自己参与的项目 + 同事名单。招聘由人事行政负责，秘书不直接调用 hire_employee。

员工之间可以直接沟通：任何员工都能用 contact_employee 找同事确认事情，不需要老板转述；每个员工使用自己的公司工具身份（员工 ID + 令牌）访问数据，不会串到别人账号。沟通过程会同时写进双方对话，右侧员工栏也能看到「正在执行：任务名」。

同事在忙不会卡住：对方正在执行任务或对话时，contact_employee 会立即返回「已送达」，消息进入收件箱；对方空闲后自动处理并把回复写进双方对话。发起员工不需要死等，稍后用 check_employee_messages 取回复。服务重启时处理中的消息会自动回到队列。

清空上下文：员工卡片上有「清空上下文」，会清掉该员工的会话记录和对话消息，员工以全新上下文开始；项目、任务、交付物和知识库记忆不会删除，适合做多轮独立测试。

项目自动推进：员工任务完成并提交交付物后，秘书会自动收到推进提示：先用 list_pending_deliverables / read_deliverable 读成果，对照验收标准用 review_deliverable 通过或打回（打回必须写清修改要求），通过后创建下一步任务并派给合适员工。老板不需要逐步安排，只有目标不清或越界时才需要拍板。

主动迭代：秘书每轮看到「项目体检」结果（项目资料、收支、证书、运维），人事每轮看到「公司体检」结果（公司信息、工具、技能、专家、知识库、服务器、设备、员工模型、模型能力、备份）；也可以在项目页点「公司体检」，按「全部 / 项目 · 秘书 / 公司 · 人事」查看并生成维护任务，项目缺口派给秘书，公司域缺口派给人事。

5.8 对话框能力

  • 附件：输入框左侧「文件 / 图片」，或直接把文件拖进对话；粘贴图片也可以（Ctrl+V）
  • 截图：点「截图」或按 Alt + Shift + A，桌面端直接截取主屏幕并生成图片附件；浏览器环境回退到系统屏幕选择器
  • 附件去向：保存到该员工工位的 attachments/，员工用 read 工具读取；图片会随消息一起送到模型
  • 模型选择：输入框右侧下拉，按对话记忆选择；「思考强度」支持快速/标准/深度（模型不支持时自动回退）
  • 提问卡：见 5.7，提交后会自动作为新消息发回员工
  • 滚动：只有停在底部时才自动跟随新消息；往上翻历史不会被拽回去。有新内容时右下角出现「回到最新 ↓」，点一下平滑回到底部。状态轮询和流式输出只更新变化的部分，不会整块重建消息；展开的工具卡、正在看的消息、切换前的滚动位置都会保留
  • 思考过程：模型返回的 reasoning 会实时显示，生成中默认展开，完成后折叠成「思考过程 · N 字」，点开可回看
  • 工具调用：每次调用一行，显示工具名、参数摘要、执行状态；点开可看完整参数与返回结果，失败标红
  • 规范输出：Markdown 正常渲染——标题、列表、表格、代码块、引用、链接，不再出现 ** 和 | 原始符号
  • 提问卡：采用逐题作答（参考 DS-Bot）：输入框上方展开一张卡，一次只问一题，显示「问题 1/3」；选项带 A/B/C 键位，单选点一下自动进入下一题，多选勾完后点「下一题 / 提交」；支持「其他答案 / 补充说明」自定义输入；所有题都可以点「跳过本题」，跳过会记为「（跳过）」发给员工。收起后对话上方保留「待确认」提示条，随时点「回答」继续

6. 对话：单聊、项目群、@同事

6.1 单聊

对话坞 → 只选员工（项目留空）→ 发消息。

  • 员工按自己的角色卡回答
  • 会带上自己的技能、专家、记忆
  • 工具调用显示为卡片
  • 生成中可点 停止；中断后可 继续
  • 对话坞的项目 / 员工下拉会自动同步新建的项目和员工，不用刷新页面；切换会话时保留当前选择
  • 单轮对话最长 5 分钟（复杂扫描 / 多轮工具够用）；真的超时会保留已生成的内容和工具记录，不会整段丢失，可点「继续生成」接着写

6.2 项目群

对话坞 → 选项目 + 任意员工 → 消息会进 project:<项目ID> 群。

  • 默认由项目编制里的最多 3 人依次发言
  • 用 @姓名 可以点名，被点名的人优先发言
  • 群聊前会自动打一个项目快照（防止把工作区聊坏）
  • 群里每条消息都能一键转任务（消息下方"建任务"）

6.3 对话里的小动作

动作效果
消息 → 建任务以这条消息为标题/描述建任务，自动关联项目与负责人
任务 → 转交把任务转给另一个员工，双方都会收到系统消息
员工 → 聊一聊从专家/员工卡片直接发起对话

6.4 会话隔离

  • 单聊：employee:<员工ID>，cwd = 他在主项目的工位
  • 项目群：employee:<员工ID>:project:<项目ID>
  • 任务：employee:<员工ID>:task:<任务ID>
  • 会议：employee:<员工ID>:meeting:<会议ID>

不同场景不会串上下文，也不会串工作目录。

7. 交付物与验收

7.1 交付物从哪来

来源说明
员工任务产出任务执行完，工位里的产物自动登记为交付物（v1、v2…）
手动收取任务行 → 交付 → 从工位挑文件
本地上传交付物页 → 上传交付物，可挂到某个任务

7.2 一份任务可以有多份交付物

一个任务下所有交付物都有版本号；验收时：

  • 单份通过/打回：交付物卡片上的「通过 / 打回」
  • 全部通过：任务详情 → 交付物区 → 全部通过
  • 只要还有一份"待验收"，任务就还是「待验收」；全部处理完才「已完成」

7.3 打回

打回必须填原因。原因会：

  • 写进交付物记录
  • 系统消息发给该员工
  • 任务回到「进行中」
  • 通知中心留一条

7.4 预览

  • 交付物卡片 → 预览：文本、Markdown、图片、PDF、Office（docx/xlsx/pptx）都能看
  • 统一在 预览台 打开，带收藏和本次历史
  • 服务管理台（Grafana、Portainer 之类）也在预览台里用 iframe 打开

7.5 预览台

区域说明
左：条目列表交付物 / 文档 / 记忆 / 报表 / 服务管理台
中：查看器文本、图片、PDF、Office 预览、iframe
右上：收藏星标常看的内容，存在浏览器本地
右上：本次历史这次打开过的条目，可一键清空

8. 审批与权限 L0–L4

8.1 分级

级别场景默认策略
L0只读（读文件、查目录、检索）直接放行
L1新建文件自动放行（可在设置里关）
L2修改已有文件AI 预审 / 工位内新文件自动放行，其余审批
L3补丁 / 批量变更 / 终端写命令必须审批（低风险命令可被预审放行）
L4外部动作（发邮件、发企微、调 webhook）必须审批

8.2 审批卡长什么样

收件箱 → 写操作审批：

  • 谁、在哪个项目、用什么工具
  • 文件路径、改动预览（前 1200 字）
  • 写前快照（可回滚）
  • 批准 / 拒绝（拒绝必须填原因）
  • 本会话内同类放行：批准时可勾选，30 分钟内同一员工 + 同一工具 + 同一文件不再问

8.3 外部动作

发邮件 / 企微 / Webhook 走 L4：

  1. 员工发起 → 生成 L4 审批卡
  2. 你批准 → 写入 data/outbox/<id>.json（本地演练）
  3. 当前版本不真正外发，outbox 是审计与联调用的

8.4 L2 自动判断怎么工作

L2 不再一律弹给人，按 Auto review 分级处理：

层规则说明
确定性分级工位/项目工作区内新建文件 = low；修改已有文件、补丁、常见构建测试命令 = medium；未识别命令 = high；删除、密钥、越界、安装、推送、联网 = critical（红线）不调用模型、零成本；红线永远不进模型
Auto review 审查medium / high 交给审查模型，按 @deepseek-ai/dsh-experimental-auto-review 的 low / medium / high 口径判定 allow / deny需要设置里配置可用的模型 API Key；不可用、超时或输出不合协议一律转人工（fail-closed）

不会自动放行的：删除命令、预存文件的覆盖/删除、.git、.env、密钥与凭据、data/settings.json/store.json、项目外路径、批量补丁（L3）、外部动作（L4）。

拒绝或转人工时，审批卡会显示来源（Auto review / 红线拦截 / 运行时审批）、风险等级和理由，你仍然可以拍板。

8.5 审批策略

设置 → 审批策略，默认 Auto review，风险口径与内置 @deepseek-ai/dsh-experimental-auto-review 一致：

模式自动放行转人工
Auto review（默认）low 直接放行；medium 经审查模型确认任务已明确授权后放行high、确定性红线、审查不可用
严格（旧）只有只读命令其余全部
平衡（旧）低风险 + 中风险（规则判断）高风险、红线
全自动（旧）低 + 中 + 高（非红线）只有红线

风险口径：

风险典型场景
low项目内常规读写、分析、格式化、lint、测试、构建、非破坏性 Git、清理本会话自己创建的产物
medium删除已存在的对象或状态、force push / 改写历史、生产环境读写与部署、非敏感外部发送、权限与系统设置变更
high密钥 / 凭据 / 私有数据外泄到外部或不可信目的地，以及同等的硬禁止效果
红线删除命令、.env/.git/密钥/凭据、store.json/settings.json/token、工作区外路径、安装依赖、git push、联网下载（确定性规则，优先于模型）

要点：

  • 审查由模型完成，但用「强制工具调用」提交 risk / decision / reason，模型不能把审查样本当成任务去执行；实测 DeepSeek / GLM / Kimi / MiniMax 均可稳定返回结论
  • medium 只有在当前任务明确授权了动作、目标和范围时才放行；授权不清、范围不明或审查失败一律转人工（fail-closed）
  • 审批卡会显示风险等级、审查结论和理由；红线拦截会单独标注
  • 升级后会自动复核历史待审批里的只读命令，能放行的直接放行，不用手动清队列
  • 批准时可勾选「本会话内该文件不再询问」，30 分钟内自动放行
写操作审批卡住时，员工状态会显示「等待审批」，右栏员工页签能直接看到。

8.6 Ticket / Mandate / 策略版本

每个任务同时是一张 Ticket，带一份 Mandate（授权），执行前会复核：

  • Mandate：记录授权人、授权时间、强度（明确 / 推断）、范围（项目、动作、最高风险）和依据的审批策略版本
  • Policy 版本：每次改审批模式或自动放行都会生成新版本（v1、v2…），审批卡和审批记录会写下当时的版本，方便追溯「为什么当时放行」
  • 开工复核：授权被撤销、或审批策略收紧为严格模式时，任务不能开工，会显示「阻塞 · 待老板处理」；任务详情里可以「撤销授权 / 重新授权」
  • Ticket 阶段：待老板回答 / 待老板验收 / 阻塞 · 待老板处理 / 失败 · 待老板处理 / 排队中 / 执行中 / 等待触发 / 已结束，任务列表直接显示

9. 公司资产：员工的能力从哪来

9.1 工具（Tools）

终端命令（terminal）

  • 终端受宿主沙箱约束，但不是完全隔离：不要给不信任的员工开

9.2 技能（Skills）

技能是"做事的方法"，会写进角色卡与上下文。技能页可新建/编辑/删除/分配；内置技能不可删。

9.2.1 技能是 SKILL.md，不是关键词

每个技能都有完整的 content（Markdown），结构固定：适用场景 → 执行步骤 → 输出要求 → 验收标准。员工被分配技能后，这段内容会完整注入系统提示（最多 5 个技能，每个 1500 字）。

  • 技能页点「查看 SKILL」可以看到全文
  • 「编辑」里可以改成你们团队自己的做法
  • 新技能默认按同一骨架生成，不会只剩一句描述

9.3 专家（Experts）

专家是"某个领域的判断力"，本质是一段高质量 prompt + 元数据。

来源说明
内置公司预置的 8 位专家
WorkBuddy 导入扫本机 `~/.workbuddy/plugins/cache/expertsmy-experts/*/*/.codebuddy-plugin/plugin.json`，勾选导入
手动新建填名称、职业、描述、正文

绑定关系是双向的：

  • 专家 → 绑定员工 / 项目
  • 员工 → 专家列表

招聘时如果没指定专家，系统会按岗位名 + 技能做关键词匹配，自动绑 1–2 位。

9.4 公司知识库 / 记忆（Memories）

四级作用域：公司 / 团队 / 项目 / 员工；分类：公司制度 / 服务器 / 设备 / 服务 / 流程 / 项目参数 / 客户 / 其他。

  • 每条记忆是一个 Markdown 文件，带 frontmatter（scope / teamId / projectId / employeeId / category / tags / pinned）
  • 注入规则：员工执行任务或对话时，按相关度注入与他和当前项目相关的记忆；不再只给一句摘要，而是注入全文（每条 2000 字、总量 12000 字），设备和服务器参数、服务端口、项目流程都能直接看到
  • 秘书 / 人事行政可在对话里用公司工具 save_memory / list_memories / read_memory 维护；其他员工只能读，不能改
  • 登记服务器或扫描服务后，会自动生成一条「服务器：名称」知识（地址、端口、启动命令、服务清单），员工下一轮就能读到
  • 新建项目时填写的关键参数和流程与验收会自动生成一条项目级知识并置顶；秘书用 create_project 建项目时也可以直接传 params / process
  • 有版本历史，可回滚；文件被外部改动会提示冲突，可选"以文件为准"或"覆盖文件"
  • 决策卡拍板、交付物验收通过、会议结束、员工归档都会自动写记忆

9.5 文档管理 / 数据 / 项目文件

页面用途
文档管理公司级文档的登记、查看、归档
数据数据集登记与字段查看（CSV/表格类）
项目文件直接浏览每个项目工作区的真实文件树

9.6 员工工作区 / 工位

员工工作区：招聘时直接绑定，默认 data/workspaces/company/employees/<员工ID>/，也可以填任意已有绝对路径。员工不在项目里时，对话、终端、文件都落在这里。

项目工位：员工参与项目后，工位直接放在项目工作区下：<项目工作区>/workstations/<员工ID>/。项目建好时就给项目组成员自动创建，员工的工作区跟着项目走，老板打开项目目录就能看到每个人的产出。

操作说明
刷新重新扫描工位
文件查看工位里有什么（弹窗列出路径与大小）
归档到项目工位已在项目工作区内，文件本来就在项目里；旧版工位会一次性迁移到 workstations/

9.8 项目归档与删除

  • 项目页顶部有「进行中 / 已归档」切换；卡片右侧的「归档」会把项目移出进行中列表，数据和工作区都保留
  • 已归档项目可以「恢复项目」或「删除项目」
  • 删除只删项目记录，默认保留工作区文件；项目下还有任务或交付物时会拒绝删除，提示先归档或清理
  • 归档项目不会自动开工，手动开工也会被拒绝

9.9 数据位置与备份

  • 安装版首次启动会询问数据位置：默认在 D:\一人公司工作区（D 盘不存在时回退到「文档\一人公司工作区」），也可以另选目录；已有数据可选择迁移过去
  • 安装向导本身也支持修改程序安装目录
  • 设置 → 数据备份：显示当前数据目录，支持「打开数据目录」「立即快照」「导出 JSON」「从 JSON 恢复」
  • 快照保存在 数据目录/backups/backup-时间/，包含 store、settings、memory、uploads、experts；导出 JSON 可迁移到另一台机器
  • 恢复会覆盖当前员工、项目、任务、记忆和设置，执行前会自动再做一份快照

9.10 交付物版本与归档

  • 同一任务的多版交付物会合并成一张卡片，默认显示最新版，卡片上标注「共 N 版」；点「历史版本」可以逐版预览
  • 交付物页顶部可按活跃 / 待验收 / 已通过 / 已打回 / 已归档筛选，项目筛选自动排除已归档项目
  • 每张卡片支持「归档 / 恢复」；「归档已处理」会一次归档所有已通过、已打回的交付物
  • 删除项目时，如果项目下还有任务或交付物，会二次确认并一并归档；删除后项目、任务、交付物都不再出现在活跃列表里，工作区文件保留

9.12 设备

11. 机房：服务器与项目服务

11.1 服务器

左栏 机房 → 服务器总览：

  • 顶部：CPU / 内存 / 磁盘 / 负载 / 服务健康汇总
  • 每台服务器卡片：模式（本机 / SSH）、状态、服务数、最近检查时间
  • 添加服务器：名称、Host、模式、分组、备注；SSH 模式填端口 / 用户名 / 私钥
  • 扫描服务由秘书执行：服务器详情点「让秘书扫描」，秘书会读取监听端口、进程命令行、Docker 容器、systemd 服务，判断每个端口是什么，起人类可读的名字（ComfyUI / Ollama / Netdata…）再登记；判断依据写入备注
  • SSH 私钥：点输入框会列出 ~/.ssh 下所有可用密钥，直接选；也可以只填文件名（如 id_ed25519_srv3090），会自动到 ~/.ssh 里找。留空则用 ssh-agent / 默认密钥
  • 测试 SSH 连接：保存前就能测，返回主机名、内核、延迟；失败会直接说原因（私钥不存在 / 认证失败 / 端口不通），并在能猜到对应密钥时自动填入

14. 常见问题

Q：员工不回话 / 一直"正在思考"？ A：先看 设置 → 运行状态 的控制面是否 ok；再看模型 Base URL / Key / 模型 ID 是否正确。任务单次执行上限 180 秒，超时会标记失败并写审计。

Q：报 session limit reached？ A：0.22.0 已修复。dsh 控制面的会话上限从 32 提到 64，并在达到上限前自动回收最久未用的空闲会话；本地会话表也做了 120 条上限。若仍出现，重启 npm run dsh 即可清空。

Q：改了员工工具，为什么他行为没变？ A：工具变更会重算 preset 并热更新，但正在跑的会话不受影响，下一轮才生效。

Q：记忆没被引用？ A：检查作用域。项目记忆只在对应项目注入，员工记忆只在该员工注入；公司级才会全员可见。

Q：交付物点预览是空白？ A：种子数据里的演示交付物没有物理文件（会显示"演示交付物，还没有绑定物理文件"）。真实任务产出或本地上传的才有内容。

Q：扫描服务器报「私钥文件不存在」或 Permission denied？

A：去「机房 → 服务器 → 编辑服务器」，点「SSH 私钥」输入框，从下拉里选 ~/.ssh 下对应的密钥（例如 3090 对应 id_ed25519_srv3090），然后点「测试 SSH 连接」。能返回主机名就说明通了。Permission denied 表示这把密钥的公钥没在服务器 ~/.ssh/authorized_keys 里，需要先 ssh-copy-id 一次。

Q：端口被占用？ A：Web 用 PORT=4400 npm start 换端口；dsh 固定 3081。

Q：安装后需要装 Node.js 吗？

A：不需要。0.24 起安装包内嵌了独立 Node 24 + DSH 全部依赖（resources\dsh\），双击即用。只有直接用 Web 免安装包（dist/一人公司-Web-*.zip）时才需要本机 Node.js 18+。

Q：内嵌 DSH 之后安装包多大？

A：安装包约 150 MB，安装后占用约 592 MB（Electron 客户端 267 MB + DSH 运行时 325 MB）。安装/首次启动会比之前慢一些，之后启动与旧版相当。

Q：模型添加不了 / 点「添加自定义模型 API」没反应？

A：0.23 起已经修好：旧版那个按钮只是展开高级字段，并不是真的新增。现在「设置 → 模型设置 → ＋ 添加模型服务」会打开独立表单，保存后立即生效。如果模型列表为空，也不影响添加——旧版模型目录依赖 AI 运行时，控制面没起来就一律为空；新版本地配置优先，控制面挂了也能配置。

Q：保存模型时提示 API 端点不合法？

A：端点必须以 http:// 或 https:// 开头，并且是 OpenAI 兼容的基础地址（通常到 /v1 为止），不要填到 /chat/completions。

Q：员工能自己跑命令/跑测试吗？ A：能。给员工分配「终端命令」工具后，他可以在工位目录里执行 PowerShell / bash。只读命令自动放行，写操作与危险命令走审批。Windows 上 Python 使用宿主 PATH，启动脚本已自动把本机最新 Python 前置；如果某个工具链找不到，先在系统 PATH 里装好。

Q：员工要改我的代码，一直卡在审批？ A：收件箱 → 写操作审批。批准后可勾"本会话内同类放行"，30 分钟内同文件不再问。

Q：怎么让某个员工不接自动任务？ A：任务上的"纳入自动开工队列"关掉，或任务页顶部把"自动开工"关掉。
