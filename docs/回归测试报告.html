2.10 SSH 扫描与对话滚动修复（0.26 补充验证）

问题 1：SSH 扫描失败

现象：扫描 3090 服务器报 Warning: Identity file 13976645145 not accessible + Permission denied (publickey,password)。

根因有两个：一是「SSH 私钥路径」填的是手机号，不是文件路径，代码原样传给 ssh -i；二是 execFile 的报错只显示 Command failed: ssh ...，把 ssh 自己输出的真实原因丢掉了。

修复：

  • 私钥路径支持 ~ / 相对文件名，依次到 data/ssh、~/.ssh、当前目录解析；找不到就报「私钥文件不存在」并列出可用密钥
  • 新增 GET /api/servers/ssh-keys，设置页私钥字段改成带下拉的输入框（本机 6 把密钥全部列出）
  • ssh-test 支持未保存的表单直接测试，失败会返回原因、建议密钥，并自动填入输入框
  • sshExec 捕获 stderr，把 Permission denied / 主机指纹 / 超时 / 端口拒绝翻译成中文可执行提示
  • 增加 StrictHostKeyChecking=accept-new 与 ServerAliveInterval=5，首次连接不再因为指纹校验失败
  • 扫描结果带进程名与常见端口名（Ollama / ComfyUI / Netdata / SSH…）
  • 顺手修了远程指标内存为 0：中文 locale 下 free 输出「内存：」，改为 LC_ALL=C 并兼容匹配

2.15 Auto review 审批（0.31 补充验证）

目标：审批流程改用 @deepseek-ai/dsh-experimental-auto-review 的方式——按实际效果把每次调用分成 low / medium / high，low 直接放行，medium 只有任务明确授权才放行，high 永远拒绝；审查失败 fail-closed。

  • 沿用插件的风险口径与 allow/deny 约束（lib/auto-review.mjs 保留 REVIEW_POLICY 原文对照）
  • 审查请求改成强制工具调用：tool_choice = submit_review，模型只能通过函数参数提交 risk / decision / reason，不能继续执行任务；实测 4 个模型全部稳定返回结论
  • low 直接放行（不调用模型）；medium / high 交给审查模型；critical 红线不调用模型，直接转人工
  • 审批模式默认改为 auto-review，旧库自动迁移一次；严格 / 平衡 / 全自动保留为回退选项
  • 审批卡区分 Auto review / 红线拦截 / 运行时审批 三种来源，显示风险与理由
  • 运行时的 approval/request 现在会转成公司收件箱审批卡，不再直接抛出「dsh 请求额外权限」把任务打断

3. 发现的问题

3.1 P0 · dsh 会话上限 32 导致整站不可用（已修复）

现象

  • 回归跑到第二轮时，POST /api/chat/stream 返回 session limit reached (32)，POST /api/chat 返回 502 DSH_UNAVAILABLE
  • GET /opc-runtime/v1/health 显示 sessionCount: 32，此后任何新会话都创建失败
  • 任务页出现连续「自动执行任务失败：session limit reached (32)」

根因

  • opc-runtime-bridge 的 MAX_SESSIONS = 32，只增不删，也没有 DELETE 接口
  • 本产品按场景建会话：员工、员工:项目、员工:任务、员工:会议
  • 任务维度会话是每任务一条，10 员工 × 多任务很快超过 32 → 聊天、任务、会议全部不可用

修复

  1. opc-runtime-bridge 升级到 0.2.3-session-evict
  2. 上限 32 → 64（可用 OPC_BRIDGE_MAX_SESSIONS 覆盖）
  3. 达到上限前自动淘汰最久未用的空闲会话（prompting 中的不淘汰）
  4. 新增 GET /sessions（列表）、DELETE /sessions/:id（显式关闭，忙时 409）
  5. 记录 lastUsedAt 用于 LRU
  6. lib/dsh-bridge.mjs
  7. 遇到 SESSION_LIMIT/429 时自动回收 8 个空闲会话并重试一次
  8. 新增 listBridgeSessions / closeSession / reclaimIdleSessions
  9. 本地会话表超过 120 条时淘汰最久未用并通知 bridge 释放

验证

项目修复前修复后
连续创建 75 个会话第 33 个开始 42975 个全部成功（0 失败）
会话总数32（卡死）稳定在 64 上限内（LRU 回收 11 个）
显式关闭无接口DELETE 返回 200，63 个会话一次清空
聊天 / 群聊 / 任务全部 502/429回归 4/4 通过
修复后完整回归再跑：126/126 全绿。
